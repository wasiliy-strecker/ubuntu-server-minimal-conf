Ubuntu Server Baseline

A security-conscious Apache deployment runbook that treats validation, access recovery, and rollback as part of the setup—not as afterthoughts.

0Scope and safety boundary

This guide is a baseline for a small public web server. Replace example.com, paths, users, and retention values for the real system. Run every command deliberately; do not paste the entire page into a shell.

Do not close the current SSH session while changing SSH or firewall settings. Open a second session and verify it before ending the first.

Initial inventory

lsb_release -ds
uname -r
ip -brief address
ss -tulpn
sudo systemctl --failed
sudo journalctl -p warning -b

1Administrative access

Use a named administrator, public-key authentication, and a validated SSH drop-in. Confirm key login before disabling passwords.

sudo adduser deploy
sudo usermod -aG sudo deploy

# Add a trusted public key to /home/deploy/.ssh/authorized_keys,
# then verify a second SSH session as deploy before continuing.

sudoedit /etc/ssh/sshd_config.d/10-hardening.conf
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
X11Forwarding no
sudo sshd -t
sudo systemctl reload ssh
ssh deploy@example.com

2Network policy

Set explicit defaults, allow SSH before enabling UFW, and expose only web traffic required by the service.

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 'Apache Full'
sudo ufw enable
sudo ufw status verbose
sudo ss -tulpn

3Packages and security updates

sudo apt update
sudo apt full-upgrade
sudo apt install apache2 unattended-upgrades needrestart ufw
sudo dpkg-reconfigure --priority=low unattended-upgrades
sudo systemctl enable --now apache2

Schedule a maintenance window when an upgrade reports that a reboot is required. Review rather than automatically restart stateful application services.

4Release-oriented filesystem layout

Immutable releases plus a current symlink make deployments inspectable and rollback atomic. Apache reads application files; it does not own the release.

sudo install -d -o deploy -g www-data -m 2750 /var/www/example/releases
sudo install -d -o deploy -g www-data -m 2750 /var/www/example/shared
sudo install -d -o deploy -g www-data -m 2750 /var/www/example/releases/20260717-120000/public

# Deploy the release, then normalize permissions.
sudo find /var/www/example/releases/20260717-120000 -type d -exec chmod 2750 {} \;
sudo find /var/www/example/releases/20260717-120000 -type f -exec chmod 0640 {} \;
sudo ln -sfn /var/www/example/releases/20260717-120000 /var/www/example/current

5Apache virtual host

Create /etc/apache2/sites-available/example.com.conf. Keep overrides disabled so configuration remains visible and reviewable.

<VirtualHost *:80>
    ServerName example.com
    ServerAlias www.example.com
    DocumentRoot /var/www/example/current/public

    <Directory /var/www/example/current/public>
        Options -Indexes +FollowSymLinks
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/example.com-error.log
    CustomLog ${APACHE_LOG_DIR}/example.com-access.log combined
</VirtualHost>
sudo a2dissite 000-default.conf
sudo a2ensite example.com.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
curl --resolve example.com:80:127.0.0.1 -I http://example.com/

6TLS and certificate renewal

Point public DNS at the server before requesting a certificate. Certbot can then create the HTTPS virtual host and redirect HTTP.

sudo apt install certbot python3-certbot-apache
sudo certbot --apache -d example.com -d www.example.com
sudo certbot renew --dry-run
systemctl list-timers | grep certbot
curl -I https://example.com/

8Rollback and recovery

Keep at least one known-good release. A rollback changes the symlink, validates Apache, reloads it, and confirms the response.

sudo ln -sfn /var/www/example/releases/PREVIOUS_RELEASE /var/www/example/current
sudo apache2ctl configtest
sudo systemctl reload apache2
curl -fsS https://example.com/ >/dev/null

Back up application state separately from release files. Encrypt backups, store a copy off-host, define retention, and regularly test restoration. A backup that has never been restored is only an assumption.
